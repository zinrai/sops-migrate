# Example

This directory contains an example of how to use sops-migrate.

## Directory Structure

```
example/
├── .sops.yaml              # sops encryption key configuration
├── age/
│   └── keys.txt            # age key (generated by user)
├── sops-migrate.yaml       # sops-migrate configuration
└── secrets/
    ├── config/
    │   ├── .env.production       # ENV file (input_type: dotenv)
    │   ├── app.ini               # INI file (input_type: ini)
    │   ├── cloud_credentials.json # JSON file (no input_type, auto-detected)
    │   └── database.yaml         # YAML file (no input_type, auto-detected)
    ├── certs/
    │   └── server.key            # Certificate key (input_type: binary)
    └── ssh_keys/
        ├── id_ed25519            # SSH private key (input_type: binary)
        └── id_ed25519.pub        # SSH public key (input_type: binary)
```

## Usage

### 1. Generate age key

```bash
cd example
age-keygen -o age/keys.txt
```

### 2. Update .sops.yaml

Replace the placeholder with the public key output from step 1:

```yaml
creation_rules:
  - age: age1xxxxxx...
```

### 3. Run dry-run

```bash
export SOPS_AGE_KEY_FILE=./age/keys.txt
sops-migrate -config sops-migrate.yaml -dry-run
```

Expected output:

```
sops encrypt --input-type binary -i secrets/certs/server.key
sops encrypt --input-type dotenv -i secrets/config/.env.production
sops encrypt --input-type ini -i secrets/config/app.ini
sops encrypt -i secrets/config/cloud_credentials.json
sops encrypt -i secrets/config/database.yaml
sops encrypt --input-type binary -i secrets/ssh_keys/id_ed25519
sops encrypt --input-type binary -i secrets/ssh_keys/id_ed25519.pub

Dry run: 7 files
```

### 4. Run migration

```bash
export SOPS_AGE_KEY_FILE=./age/keys.txt
sops-migrate -config sops-migrate.yaml
```

### 5. Verify

```bash
export SOPS_AGE_KEY_FILE=./age/keys.txt
sops decrypt secrets/config/database.yaml
```

## Notes

- Files listed in `sops-migrate.yaml` are encrypted with explicit `--input-type`
- Files not listed are encrypted without `--input-type` (sops auto-detects by extension)
- `.sops.yaml` and `sops-migrate.yaml` are excluded from encryption (not under `secrets/`)
- For production use, refer to the [sops README](https://github.com/getsops/sops) for key management best practices
